# 🎆 digital-fireworks

**直径6cmの2.5号玉「型物（かたもの）」を設計して、そのまま打ち上げるシミュレーター。**

▶ **そのまま遊べます: https://sekisuihouse.github.io/digital-fireworks/**
（インストール不要。PC・タブレット・スマホのブラウザで動きます）

このアプリで作るのは「絵」ではなく、**実際に作れる花火玉そのもの**です。

```
直径 6cm の円の中に
直径 1cm の星（珠）を
6色だけ使って
重ならないように自由に並べる
        ↓
その星の並びが、そのまま夜空に開く
```

玉の中でハートに並べた星は、空でもハートに開きます。星の色は、そのまま火花の色になります。

> **割物（わりもの）の型物です。ポカ物ではありません。**
> 強い割薬で玉を内側から一気に割り、星を中心から放射状に同じ速さで押し出します。
> 星は光の尾（引き）を曳いて飛び、玉の中の並びを拡大した位置で燃えて「形」を描き、最後に揃って消えます。
> （ポカ物のように玉が二つに割れて中身がふわっと散る・垂れ落ちる表現は作っていません）

## セットアップ

**必要なもの: Node.js 18 以上だけ。**

```bash
cd digital-fireworks
```

以上です。`npm install` は不要です。
**依存パッケージはゼロ**（`package.json` の `dependencies` / `devDependencies` は空）。
ビルド工程もありません。ブラウザがそのまま読める ES Modules で書かれています。

> このフォルダは完全に独立しています。
> `handwritten-fireworks` など他プロジェクトとのコード共有・共通パッケージ・共通エンジン・import は一切ありません。

## 起動方法

> ブラウザで試すだけなら https://sekisuihouse.github.io/digital-fireworks/ を開くだけです。
> 以下はローカル（会場PC・オフライン）で動かす場合の手順です。

```bash
npm run dev
# または
node server.mjs
```

```
  🎆  digital-fireworks
  ─────────────────────────────────────
  ローカル:  http://localhost:5180/
  停止:      Ctrl + C
```

ブラウザで **http://localhost:5180/** を開きます。

ポートを変えたいとき:

```bash
node server.mjs --port 8080
PORT=8080 node server.mjs
```

Node を使わず、他の静的サーバでも動きます（`file://` 直開きだけは ES Modules の制約で不可）。

```bash
python3 -m http.server 5180
```

**起動後はネット接続不要です。** 設計・試し打ち・保存・再生・ギャラリーはすべてオフラインで動きます。
外部 API・CDN・外部 Web フォント・画像ファイルへの依存はありません（アイコンはインライン SVG、効果音は WebAudio の合成音）。

## 使いかた

**操作はこの 3 ステップだけです。**

```
① いろを えらぶ  →  ② まるの なかに ならべる  →  ③ うちあげる
```

### ① いろを えらぶ

左（スマホ・タブレットでは下）のパレットから **6色のうち 1 色**を選びます
（あか / レモン / みどり / むらさき / あお / しろ）。
ここで決まるのは「**つぎに おく ほし**」の色です。

### ② まるの なかに ならべる

| したいこと | 操作 |
| --- | --- |
| 星を置く | まるの中を **タップ（クリック）** |
| 星を動かす | 置いた星を **ドラッグ** |
| 星の色を変える | 色を選んでから、その星を **タップ** |
| 星を消す | **けしゴム**を押してから星をタップ／右クリック／`Delete` |

**グリッドはありません。** 星はタップした位置にそのまま置かれます。
制約は「重ならないこと」と「円からはみ出さないこと」だけです。

狙った場所が塞がっているときは、**すぐ近く（最大 0.9cm）の空いている場所を探して置きます**。
円のふちを狙ってはみ出す場合も、中心方向へ引き戻して置きます。
大まかに狙っても置けるので、こどもでも形を作りやすくなっています。
（ドラッグ中のゴーストは「実際に置かれる場所」に出るので、見た目と結果は必ず一致します）

近くにも空きがないときだけ置けません。そのときは **半透明の赤い ×** と、
**ぶつかっている星のまわりの赤い破線の円（1cm の範囲）** で理由を示します。

| 出るメッセージ | 理由 |
| --- | --- |
| たまが まるから はみだしちゃう | 円の外すぎて、引き戻しても入らない |
| たまが かさなっちゃう | まわりが埋まっていて、近くにも空きがない |
| もう ほしを おく ばしょが ないよ | 玉が満杯（最大 19 個前後） |

左パネルの補助ボタン:

| ボタン | 動作 |
| --- | --- |
| **おてほん** | ハート・ほし・にこちゃんなど 7 種のプリセットを読み込む |
| **ぜんぶ うめる** | 空いているところを、いま選んでいる色で一気に埋める |
| **ぜんぶ けす** | 星を全部消す（「もどす」で復活できる） |

矢印キーで 0.05cm ずつ（`Shift` で 0.3cm）微調整できます。

### ③ うちあげる

| ボタン | 動作 |
| --- | --- |
| **うちあげる** | 夜空をかぶせて再生。終わると自動で編集に戻る |
| **ぜんがめん** | 同じ再生を全画面で（プロジェクタ投影用） |
| **ほぞん** | 名前をつけてギャラリーへ保存 |

### ギャラリー

保存した花火玉の一覧。**うちあげる / へんしゅう / ふくせい / さくじょ**ができます。

**「みんなの花火を 打ち上げる」** を押すと、
保存した全員の玉を作った順に 1 発ずつ打ち上げ、最後に全部を混ぜた**フィナーレ**を再生します。

### キーボード

| キー | 動作 |
| --- | --- |
| `1` 〜 `6` | つぎに置く星の色を選ぶ |
| `↑ ↓ ← →` | 選んだ星を微調整（`Shift` で大きく） |
| `Space` | うちあげる |
| `Ctrl/⌘ + Z` | もどす（Undo） |
| `Ctrl/⌘ + Shift + Z` / `Ctrl + Y` | やりなおす（Redo） |
| `Ctrl/⌘ + S` | ほぞん |
| `Delete` / `Backspace` | 選んだ星を消す |
| `Esc` | 選択解除 / けしゴム解除 / 再生中はキャンセル |
| 右クリック | その星を消す |

### 画面のサイズ

PC・プロジェクタ（1920×1080）を第一想定にしつつ、
**タブレット・スマホでも 1 画面に収まります**（パレットが夜空の下に回り、
ボタンはアイコンだけになります）。タッチ操作はマウスと同じです。

## 2.5号玉の制作条件

このアプリが必ず守るルールです。**データモデル・配置判定・保存・編集・花火シミュレーションのすべてに一貫して反映**されています。

| 項目 | 値 | 実装場所 |
| --- | --- | --- |
| 花火玉の外周 | 直径 **6cm**（半径 3cm） | `SHELL_DIAMETER_CM` |
| 星 1 個 | 直径 **1cm**（半径 0.5cm） | `PELLET_DIAMETER_CM` |
| 星の中心が入れる範囲 | 中心から **2.5cm 以内**（`√(x²+y²) ≤ 2.5`） | `MAX_PELLET_CENTER_R_CM` |
| 星どうしの最小距離 | **1.0cm 以上**（`distance(a,b) ≥ 1.0`） | `MIN_PELLET_GAP_CM` |
| 星の色 | **6色のみ**（赤 / レモン / 緑 / 紫 / 青 / 白） | `PELLET_COLORS` |
| 配置 | **自由座標**（グリッドスナップなし） | `state.resolvePosition()` |
| 星の個数上限 | **24 個**（最密の六角配置なら 19 個入る） | `MAX_PELLETS` / `hexSlots()` |

すべて `src/types/shell.js` と `src/data/pellet-colors.js` の 1 か所で定義しています。

実装していないもの（意図的に禁止）:

- 直径6cmの円からはみ出した星
- 星どうしの重なり
- 1cm 以外の星サイズ
- 6色以外の星 / RGB カラーピッカー / 任意色指定
- 物理制約を無視した画像→花火変換
- 任意の絵をそのまま 1 発の花火として表示
- ポカ物（玉が割れて中身が垂れ落ちる表現）

## 技術構成

| 項目 | 採用 | 理由 |
| --- | --- | --- |
| フレームワーク | **なし**（Vanilla JS + ES Modules） | ビルド不要・`npm install` 不要・オフラインで確実に動く |
| 描画 | **Canvas 2D（2レイヤー構成）** | WebGL を使うほどの 3D 表現は不要。数千パーティクルなら Canvas 2D のバッチ描画が軽い |
| 型 | JSDoc による型注釈 | TypeScript のビルド工程を持ち込まずに型の意図を残す |
| 状態管理 | 単一ストア（`src/app/state.js`）+ 自前の小さな EventEmitter | 依存ゼロ |
| 保存 | **localStorage** | 外部DB不要。サムネイル込みで 1 発あたり約 10KB |
| 効果音 | **WebAudio によるプロシージャル合成** | 音声ファイル 0 個。オフラインで鳴る |
| アイコン | インライン SVG | 外部アセット 0 個 |
| 開発サーバ | `server.mjs`（Node 標準モジュールのみ） | 依存ゼロ |

**ブラウザ要件:** Chrome / Edge / Safari / Firefox の現行版（ES Modules・Canvas 2D・`Path2D`・`ResizeObserver`）。

## FireworkShell / Pellet データ構造

```js
/**
 * @typedef {object} Pellet
 * @property {string} id
 * @property {number} x      cm（玉の中心が原点・右が +）
 * @property {number} y      cm（玉の中心が原点・下が +）
 * @property {string} color  PELLET_COLORS の id
 *
 * @typedef {object} FireworkShell
 * @property {string} id
 * @property {string} name
 * @property {Pellet[]} pellets
 * @property {number} createdAt
 * @property {number} updatedAt
 */
```

実例（ハートの一部）:

```json
{
  "id": "shell_muc6qg6s_2f1",
  "name": "ハートの花火",
  "pellets": [
    { "id": "pel_1", "x": -1.004, "y": -1.739, "color": "red" },
    { "id": "pel_2", "x":  1.004, "y": -1.739, "color": "red" },
    { "id": "pel_3", "x":  0.0,   "y":  0.0,   "color": "white" },
    { "id": "pel_4", "x":  1.905, "y":  1.502, "color": "lemon" }
  ]
}
```

**座標は cm の実寸です。** `x² + y² ≤ 2.5²` と、任意の 2 星で `distance ≥ 1.0` が常に成り立ちます。

保存時は次のレコードになります。

```js
/**
 * @typedef {object} ShellRecord
 * @property {string} id
 * @property {string} name
 * @property {FireworkShell} shell
 * @property {string} thumbnail   dataURL (image/jpeg 192×192, 約10KB)
 * @property {number} createdAt
 * @property {number} updatedAt
 */
```

localStorage のキー:

| キー | 内容 |
| --- | --- |
| `digital-fireworks.v2.shells` | 保存した花火玉の配列 |
| `digital-fireworks.v2.settings` | 音 / 選択中の色 |
| `digital-fireworks.v2.draft` | 編集中の下書き（リロードしても消えない） |

読み込みは必ず `normalizeShell()` を通し、制約を破っている星は捨てます。
**無効なデータがアプリに入ることはありません。**

## 配置判定（canPlacePellet）

配置の可否を判定するのは、この 1 つの関数だけです。
UI（ゴースト表示・クリック・ドラッグ）も、プリセット読み込みも、保存データの復元も、すべてここを通ります。

```js
import { canPlacePellet } from './src/types/shell.js';

/**
 * @param {number} x cm
 * @param {number} y cm
 * @param {Pellet[]} existingPellets
 * @param {{ignoreId?: string}} [opts]  ドラッグ中に自分自身を無視する
 * @returns {{ok:boolean, reason?:'outside'|'overlap'|'full', conflictId?:string}}
 */
canPlacePellet(x, y, existingPellets, opts);
```

判定内容:

1. **外周からはみ出さないか** — `√(x² + y²) ≤ 2.5cm`
2. **既存の星と重ならないか** — すべての星に対して `distance ≥ 1.0cm`
3. 個数の安全弁 — `MAX_PELLETS`

関連関数:

関連関数:

| 関数 | 用途 |
| --- | --- |
| `isInsideShell(x, y)` | 1 の判定だけ |
| `validateShell(shell)` | 玉全体を検査（`{ok, errors[]}`） |
| `normalizeShell(raw)` | 保存データを読み込み、違反した星を落とす |
| `hexSlots()` | 最密の六角配置（19 か所）。おてほんの定義と自動配置の候補に使う |
| `findFreeSpot(pellets)` | 空いている場所をひとつ探す（「ぜんぶ うめる」用） |
| `findNearbySpot(x, y, pellets, opts)` | 狙った場所がダメなとき、**すぐ近く**の置ける場所を探す |
| `isShellFull(pellets)` | もうどこにも置けないか（「まんぱい」表示用） |

### 近場さがし（`findNearbySpot`）

狙った座標に置けないとき、**0.1cm きざみで最大 0.9cm** まで周囲を探して、
いちばん近い置ける場所を返します。円の外なら先に中心方向へ引き戻した点を試します。
見つからなければ `null` を返し、そのときだけ配置を断ります。

```js
findNearbySpot(2.9, 0, [])        // -> { x: 2.5, y: 0, snapped: true }   円のふちへ引き戻す
findNearbySpot(0.2, 0, [center])  // -> { x: 0.62, y: -0.80, snapped: true } 隣の空きへ
findNearbySpot(4, 4, [])          // -> null                                 遠すぎる
```

**置く／動かすときに実際に使われる座標は `state.previewSpot()` で先に取れます。**
ゴースト表示はこの座標に出るので、**見えている場所と、離したときに置かれる場所は必ず一致します**。

**ドラッグ移動も同じ判定を通ります。** ドロップ先が塞がっていても近くに空きがあればそこへ、
近くにも空きがなければ星は**元の位置に戻ります**（`state.movePellet()` が `{ok:false}` を返し、状態を変えない）。

## 色の変更・追加方法

`src/data/pellet-colors.js` の `PELLET_COLORS` **1 か所だけ**を書き換えます。
パレット UI・星の描画・サムネイル・火花の色がすべて自動で追従します。

```js
export const PELLET_COLORS = [
  {
    id: 'red',                 // 保存される値
    name: 'あか',               // 画面表示名
    swatch: '#ff3b4a',         // パレットと星の表示色
    particles: [               // 打ち上げ時の火花色（1粒ごとに選ばれる）
      '#ff1a2e', '#ff3a44', '#ff5c48', '#ff8f63',
    ],
    twinkle: 0.12,             // 0..1 瞬きの強さ
    glow: 1.0,                 // 明るさ倍率
  },
  // 以下 lemon / green / purple / blue / white（この順に画面へ並ぶ）
];
```

配列の**順番がそのままパレットの並び**になります。
昔の保存データに無い色 id（`yellow` など）は `COLOR_ALIASES` で読み替えるので、
色を入れ替えても保存済みの作品は壊れません。

色数は 6 が前提です（`PELLET_COLOR_COUNT`）。
数を変えるとコンソールに警告が出ます。UI には常にこの配列の色だけが並び、
RGB ピッカーや任意色指定は存在しません。
保存データに未知の色 id があっても `getPelletColor()` が既定色へ矯正します。

## おてほん（プリセット）の追加方法

`src/data/shell-presets.js` に 1 要素足すだけです。
座標は最密の六角配置の **行・列** で書けるので、絵として並べられます（ユーザー側は自由配置）。

```
row -2 : col -1, 0, 1
row -1 : col -2, -1, 0, 1     （半個ぶん右にずれる）
row  0 : col -2, -1, 0, 1, 2
row  1 : col -2, -1, 0, 1
row  2 : col -1, 0, 1
```

```js
{
  id: 'cross',
  name: 'じゅうじ',
  hint: 'たてよこに ならべる',
  pellets: P([
    [-2, 0, 'blue'],
    [-1, -1, 'blue'], [-1, 0, 'blue'],
    [ 0, -2, 'blue'], [0, -1, 'blue'], [0, 0, 'white'], [0, 1, 'blue'], [0, 2, 'blue'],
    [ 1, -1, 'blue'], [1, 0, 'blue'],
    [ 2, 0, 'blue'],
  ]),
}
```

万一はみ出した座標を書いても、`createShell()` が `canPlacePellet()` を通すため
**不正な星はアプリに入りません**（黙って捨てられます）。

## 花火エンジンの構造

`src/fireworks-engine/` はこのアプリ専用です。他プロジェクトのエンジンは使っていません。

### 星 → 火花の対応（いちばん大事なところ）

実際の型物花火は、玉の中に並べた星が割薬で球状に押し出され、
**玉の中の並びがそのまま拡大されて空に現れます。** このエンジンも同じ計算をしています。

```
星の位置 (x, y)[cm]
      ↓  ÷ 2.5cm         （星が置ける限界で正規化 → -1..1 の方向ベクトル）
方向ベクトル (dx, dy)
      ↓  × 開花半径 R × 空気抵抗 DRAG
火花の初速 v0
      ↓  空気抵抗で減速（時定数 1/DRAG ≒ 0.33 秒）
最終的な到達位置 = 方向 × R   ← 玉の中の並びが R 倍に拡大された形
```

- 星 1 個 = 尾（引き）を曳く明るい芯 1 粒 + 芯に寄り添う小さな火の粒 約 10 個。
  ばらけ幅（`PELLET_SPREAD = 0.03`）は星の間隔（0.4）よりずっと小さい → 空でも「星 1 個 = 1 つの光点」
- 星の色 → そのまま火花の色（`PELLET_COLORS[].particles`）
- 中心の星（0,0）は方向ベクトルが 0 なので、爆心にとどまる

**割物の型物らしく見せるための設定**（ポカ物にしないため）:

| 値 | 設定 | ねらい |
| --- | --- | --- |
| 割薬の閃光・白い火花・「ドン」 | 強め | 強い割薬で玉が一気に割れる瞬間を見せる |
| 星の空気抵抗 `DRAG × STAR_DRAG_MUL(0.8)` | 時定数 ≒ 0.42 秒 | 中心から形まで尾を曳いて飛ぶ様子が見え、所定の位置で止まる |
| 引き（`_tailEmitter`） | 飛んだ道に光を置く | 中心から放射状の線 → 割物らしい開き |
| `GRAVITY = 0.1` | 重力を弱く | 開いた形が垂れて崩れない |
| 星の寿命 `STAR_LIFE = 2.3` 秒 ＋ 1発ごとのばらつき 0.2 秒 | 揃える | 形が読み取れる時間を確保し、最後に一斉に消える（消え口） |
| 初速のばらつき ±1.5% | 小さく | 星が一斉に同じ距離まで開いて形がそろう |

`BURST_RADIUS = 0.34`（ステージ高さ基準）が 2.5cm に対応します。ここを変えると開花の大きさが変わります。

### レイヤー構成

```
┌──────────────────────────────┐
│ fxCanvas  花火（毎フレーム描画）  │  destination-out で薄く消す → 残像が出る
├──────────────────────────────┤
│ bgCanvas  夜空・星・地平線       │  リサイズ時だけ描き直す
└──────────────────────────────┘
```

2枚に分けているのは、残像フェードで星や地平線まで消えるのを防ぐためです。

### 1発の流れ

```
launch(shell)
   ↓
_launchShot()   地面（y=1.02）から発射・打ち上げ音
   ↓
_updateShells() 減速しながら上昇（ease-out）。前フレームとの間を補間して光跡を撒く
   ↓  指定の高さに到達
_burst()        割薬の光 + 星の配置どおりに火花を生成 + 開花音
   ↓
particles.update()  空気抵抗 → 重力 → 移動 → 寿命
   ↓
particles.draw()    明るさ順に減光・瞬き・ブルーム
   ↓
寿命切れ / 地面より下 で消滅
```

### 主要ファイル

| ファイル | 役割 |
| --- | --- |
| `engine.js` | 2枚のキャンバス管理、rAF ループ、打ち上げ、開花（星→火花）、自動品質調整 |
| `particles.js` | パーティクル本体。Structure-of-Arrays（型付き配列）で GC を出さない |
| `sky.js` | 夜空背景と `computeStage()`（16:9 ステージ矩形の計算） |
| `palette.js` | 色文字列をインデックス化して描画をバッチ化する |
| `audio.js` | 打ち上げ「ヒュー」と開花「ドン」を WebAudio で合成 |

### 描画が速い理由

1. **Structure-of-Arrays** — 位置・速度・寿命を `Float32Array` で持ち、1粒ごとのオブジェクトを作らない
2. **バッチ描画** — 「色 × 明るさ(6段階) × 太さ(4段階)」でまとめ、1バケツを 1 本の `Path2D` にして `stroke()` 1〜2回。数千粒でも stroke 呼び出しは数十回
3. **線分で描く** — 前フレーム位置から現在位置へ線を引くので、それ自体が軌跡になる
4. **残像はキャンバスのフェード** — `destination-out` で毎フレーム少しずつ消すだけ

### 物理パラメータ（`particles.js`）

```js
export const GRAVITY = 0.1;   // ステージ高さ / 秒²（型物なので重力は弱め）
export const DRAG    = 3.0;   // 1秒で exp(-3.0) 倍に減速（≒0.33秒で開ききる）
```

初速は `v0 = R × DRAG` で決めています。空気抵抗のもとで到達距離がちょうど `R` になるため、
`BURST_RADIUS` がそのまま見た目の開花半径になります。

### 自動品質調整

0.5 秒ごとに実 fps を測り、42fps を下回ると火花数の係数を最小 0.45 まで落とします。
56fps を超えると戻ります。プロジェクタでも 30fps を割らないための保険です。

### コマ送り（デバッグ）

```js
digitalFireworks.store.state.shell        // 編集中の玉
digitalFireworks.storage.listShells()     // 保存済み一覧
digitalFireworks.player.launchShell(shell)
```

## 本番（ワークショップ）での使い方

### 準備（前日まで）

1. 会場PCに Node.js 18 以上を入れる
2. このフォルダをコピーする
3. `node server.mjs` で起動できることを確認する（**当日はネット不要**）
4. プロジェクタを 1920×1080 で接続し、ブラウザをそのディスプレイへ移動する

### 当日の流れ

**1. 設計（ひとり 1 台、または交代制）**

- 「おてほん」から選ぶと最初の一歩が速い
- **いろを えらぶ → まるの なかを タップ → うちあげる**、をくり返す
- できたら **ほぞん**（名前は本人に入れてもらう）

**2. 1 発ずつの披露**

- ギャラリー → カードの 🚀 で、その玉だけ全画面で打ち上げ（編集画面の「ぜんがめん」でも同じ）
- 作品名が出てから花火が上がります

**3. 最後に「みんなの花火」**

- ギャラリー → **みんなの花火を 打ち上げる**
- `みんなの花火大会`
  → 作品1（名前を表示 → 打ち上げ）
  → 作品2 …（**古い順＝作った順**）
  → **フィナーレ**（全員の玉を混ぜて波状に打ち上げ、最後に一斉打ち）
  → `おしまい`
- 途中でやめたいときは `Esc` か右上の「とじる」

### 複数PCで作った作品を1台に集める

1. 各PCのギャラリーで **バックアップ** → JSON ファイルが保存される
2. 上映用PCのギャラリーで **よみこみ** → JSON を選ぶ（既存の作品にマージされます）
3. **みんなの花火を打ち上げる**

### 本番のコツ

- 上映前に音量を確認する（右上のスピーカーで ON/OFF）
- 会場を暗くすると発色がかなり良くなります
- ブラウザは全画面（`F11` / `⌃⌘F`）にしておくとタブが映りません
- 作品は各PCの localStorage に入ります。**ブラウザの「閲覧履歴の削除」で消えます**。
  大事な作品は必ず **バックアップ** を取ってください

## パフォーマンス

想定: **1920×1080 プロジェクタ / 最低 30fps / 目標 60fps**

実測（Chrome / Apple Silicon / devicePixelRatio 2）:

| シーン | 同時パーティクル | 平均フレーム時間 | p99 |
| --- | --- | --- | --- |
| 1 発（星 14 個のハート） | 約 450 | 0.5 ms | — |
| フィナーレ（13 発・波状） | 約 3,600 | 1.7 ms | 7.7 ms |

| devicePixelRatio 上限 | `engine.js` の `MAX_DPR` | 2 |
| 星の個数上限 | `types/shell.js` の `MAX_PELLETS` | 24 |

## よくあるトラブル

| 症状 | 原因と対処 |
| --- | --- |
| 真っ白な画面／何も出ない | `file://` で直接開いている。ES Modules は使えないので `node server.mjs` 経由で開く |
| 星が置けない | 円からはみ出すか、他の星と重なっている。赤い破線の円を避けて置く |
| 音が鳴らない | ブラウザの自動再生制限。一度どれかのボタンを押すと鳴る。右上のスピーカーも確認 |
| 保存できない | プライベートウィンドウなどで localStorage が使えない。通常ウィンドウで開く |
| 作品が消えた | ブラウザの閲覧データを削除すると消える。**バックアップ** から復元する |
| 全画面にならない | Fullscreen API が拒否されても再生自体は続きます。`F11` で手動全画面に |
| 動きがカクつく | 他のタブ・アプリを閉じる。自動品質調整が効くまで数秒かかります |
